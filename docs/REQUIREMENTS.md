# URL Downloader（URL下载器）产品需求冻结

版本：DEV-01 基线  
平台：Windows 10 / Windows 11  
状态：文字需求已整理；见文末待确认项

## 1. 产品目标与用户

URL Downloader（URL下载器）是面向 Windows 用户的桌面下载器。普通用户可直接下载 HTTP/HTTPS URL；高级用户可用规则批量生成地址，第一版内置 Jenkins HPI 规则。最终交付为无需预装 Python、Node.js 或 npm 的 Windows 程序。

## 2. 功能需求

### 2.1 直接 URL

- 输入一行一个 URL；允许单条或多条，忽略空行。
- 仅接受绝对 HTTP/HTTPS URL。无效行需说明原因；有效行仍可加入队列。
- 默认文件名取 URL 路径最后一段，不含 query/fragment。没有可用文件名时生成安全的 `download_<时间戳>` 名称。
- URL 验证、文件名规范化及路径限制由后端统一执行。

### 2.2 规则下载

- 提供内置 Jenkins HPI 规则，并保留原有 HPI 批量下载的主要使用方式。
- 用户可以新增、查看、编辑、删除自定义规则；自定义规则和选择项重启后保留。内置规则不可删除或修改。
- URL 模板变量：`{base_url}`、`{name}`、`{version}`、`{filename}`、`{ext}`。
- 规则包含 URL 模板、本地文件名模板和默认扩展名；提供预览。
- 预览与创建任务必须调用相同的 Renderer。
- 批量输入逐行解析；错误行指出行号和原因，其他有效行继续处理。

### 2.3 下载队列

- 任务展示文件名、状态、进度和错误摘要；显示总体进度及当前下载状态。
- 状态至少包括：等待中、下载中、等待用户、已完成、失败、已取消。`等待用户`用于冲突处理。
- 并发数可配置为 1–32，默认 4。
- 支持停止单个任务、重试单个失败任务及重试全部失败任务。
- 用户取消后不自动重试，保留 `.part` 以便用户之后重试或恢复。

### 2.4 下载、恢复和重试

- 文件先流式写入同目录的 `<filename>.part`；成功后用原子替换提交到目标文件。
- 对已有 `.part` 发送 `Range: bytes=<size>-`。收到 206 时续传；服务器忽略 Range 并返回 200 时从头写入，并在界面提示续传未被支持。其他不符合预期的响应按 HTTP 错误策略处理。
- 网络超时、连接中断和指定服务器错误可自动重试，默认最多 3 次，退避间隔为 1、2、4 秒。普通 4xx、非法路径和用户取消不自动重试。
- 网络失败和应用关闭不能将半成品误标为完成。程序安全退出须停止接收新任务、关闭下载流、保存任务状态并等待后台服务停止。

### 2.5 文件冲突与路径

- 输出根目录由用户选择，可选子目录；空子目录表示直接保存到根目录。
- 支持覆盖、重命名、跳过、询问用户四种冲突策略。发生询问时任务进入等待用户状态，并释放下载并发槽。
- 文件名、子目录及最终解析路径均须校验；阻止路径穿越，并处理 Windows 保留名称。
- **基线解释**：初始冲突策略采用“询问用户”，符合“未选择覆盖则提示”的明确要求。若用户在设置中选择覆盖/重命名/跳过，则按已保存策略处理。此解释待产品方确认。

### 2.6 设置、历史与日志

- 持久化输出目录、并发数、当前模式、自定义规则、重试次数、冲突策略等偏好。
- 保存任务及下载历史，异常退出后把遗留的下载中任务恢复为等待中；若 `.part` 存在则可继续续传。
- 记录任务创建、开始、完成、失败、取消、重试、冲突及规则错误等事件。日志含时间、任务名、URL、状态和错误摘要；界面可查看近期日志并导出。

## 3. 非功能要求

- 技术栈固定为 Vue 3、TypeScript、Vite、Pinia、自定义 CSS、pywebview、FastAPI、Uvicorn、asyncio、httpx、aiofiles、SQLite、aiosqlite、WebSocket、PyInstaller。变更需明确批准。
- FastAPI 仅监听 `127.0.0.1` 随机端口；前端 API 调用携带当前进程的随机 Session Token；禁止任意 CORS 和局域网访问。
- UI 按用户提供的参考图 1:1 实现。参考图优先于文字视觉描述。
- 至少适配 1024×768、1124×1068、1366×768、1440×900、1920×1080 及 Windows DPI 100%、125%、150%；不得裁切、重叠或中文乱码。
- 单文件和 portable 目录版均须在未安装 Python/Node.js 的 Windows 环境运行。

## 4. 验收摘要

单条/多条直接下载、HPI 与自定义规则、预览一致性、队列状态和操作、并发、重试、取消、Range 恢复、冲突处理、路径安全、偏好持久化、历史、日志、安全退出、重启恢复、本地 API 安全、UI 参考图验收和 Windows 打包均纳入验收。详见 `ACCEPTANCE_CHECKLIST.md`。

## 5. 待确认项

1. UI 参考图尚未随当前项目文档提供；在其提供前不能冻结颜色、尺寸、间距和像素级布局。
2. 需求称“保留原有 HPI 批量下载方式”，但原程序、样例输入及现存 HPI 行为说明未提供。应在 DEV-10 前取得样例并冻结解析格式和默认值。
3. 初始冲突策略采用询问用户，是根据需求文字作出的基线解释，请确认。
4. “文件名默认取 URL 路径”与服务器 `Content-Disposition` 文件名的优先级未定义；第一版按明确 URL 路径规则，不自动改用响应头，除非后续需求确认。
5. “总体进度”的计算口径（已知总字节加权或任务平均）未定义，UI 阶段结合参考图冻结。
